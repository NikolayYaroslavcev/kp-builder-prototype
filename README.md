# Сборка КП: прототип

Внутренний инструмент менеджера: собрать коммерческое предложение по сделке из Битрикс24 по товарам из каталога PIM, проверить его и сохранить в сделку.

Демо: https://nikolayyaroslavcev.github.io/kp-builder-prototype/

## Сценарий менеджера

1. Выбрать сделку: клиент и контакт подтягиваются из сделки, черновик по ней восстанавливается.
2. Добавить товары: строка с подсказками по артикулу или названию (`/` ставит в неё курсор, стрелки и Enter выбирают), каталог с фильтром и страницами или вставка списка из письма клиента с проверкой строк до добавления.
3. Задать количество и скидку: итог и НДС пересчитываются сразу.
4. Исправить то, что показали проверки в строках и в панели «Готовность КП».
5. Посмотреть черновик, сохранить КП в сделку: появляется версия с номером, её можно открыть и распечатать в PDF.

## Проверки (раздел 4 документа)

| Ситуация | Поведение |
|---|---|
| Нет цены, товар снят с продажи, артикула больше нет в PIM | Ошибка в строке, строка не входит в итог, КП не формируется. «Найти замену» подбирает аналог и ставит его на место строки с тем же количеством и скидкой |
| Количество не целое число от 1 до 99 999, скидка вне 0–99%, запись вроде «1e3» | Ошибка в строке, поле красное, строка не входит в итог |
| Тот же артикул ещё раз | Количество суммируется |
| Скидка выше лимита менеджера (10%) | Предупреждение; сохранить в сделку можно после отметки «согласована с руководителем» |
| Цена не обновлялась больше 90 дней | Предупреждение |
| Цена в PIM изменилась после добавления в черновик | Показаны старая и новая цена, КП не формируется, пока менеджер не примет новую (по одной или все сразу) |
| PIM не отвечает | Плашка с кнопкой «Повторить», черновик на месте, КП не формируется до сверки цен |

«PIM не отвечает» и смена цены включаются в блоке «Демо-режим и допущения».

## Устройство

- Без сборки и зависимостей: HTML, CSS, JavaScript (ES-модули), шрифты лежат в репозитории.
- `pim.js`: имитация API PIM с асинхронными ответами: поиск, фильтр и страницы выполняются «на стороне PIM», браузер не получает весь каталог. Для подключения настоящего API меняется только этот модуль.
- `data.js`: условные данные: 118 товаров, 6 сделок, настройки (ставка НДС, лимит скидки, срок актуальности цены).
- `app.js`: интерфейс и проверки. Черновик и версии по каждой сделке хранятся в браузере.

## Допущения, которые нужно сверить до реализации

- Цены в PIM с НДС, ставка 22%.
- Запрос в Битрикс24 (в демо не отправляется): `crm.deal.productrows.set`, `PRICE`: цена за единицу после скидки с НДС, `TAX_INCLUDED: Y`. Метод заменяет все товарные строки сделки, что подходит для модели «сделка = последняя версия КП». Связь с товаром каталога Битрикс24 (`PRODUCT_ID`) требует сопоставления артикулов PIM. Способ прикрепления PDF к сделке уточнить.
- Номер КП присваивается при сохранении в сделку, поэтому предпросмотр печатается как черновик.
- КП действует 14 дней с даты сохранения.

## Проверка

Автотест в браузере (Playwright), 75 проверок: все примеры приёмки из раздела 4, быстрый ввод с клавиатуры и смена сделки во время ответа PIM, замена товара, отмена удаления, вставка списка в разных форматах, согласование скидки, печать длинного КП, перезагрузка, телефон.
